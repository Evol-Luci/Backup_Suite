# External-writer handoff contract — design

Status: proposal for review, 2026-10-30. Design only; no automatic apply or writer protocol is implemented here. Baseline: `bbf6c1a`.

## Question and falsification rule

The question is whether automatic apply can replace the person's `--writers-paused` acknowledgement with machine-verifiable evidence. Before source inspection, the premise would be falsified if the current apply path already acquired durable, destination-scoped exclusion honored by every supported external writer, checked it at the last mutation boundary, and recovered it after a crash. The proposed contract would then duplicate an existing one. A later implementation would be falsified by one supported enrolled writer obtaining or using a write grant after it acknowledged the matching pause epoch and before resume.

Source inspection did **not** find that exclusion. Solace gives an external tool a workspace path but does not launch, stop, or sandbox it (`docs/task-workspaces.md:37`). `writers_paused=true` is a caller assertion required for apply and recovery (`solace_core/integration_protocol.py:12,16-40`; `solace_core/integration_operations.py:118,226`; `solace_core/integration_recovery.py:77-80`). Durable target and journal claims coordinate Solace operations (`solace_core/integration_claims.py:215-269`); they do not intercept direct editor writes. Current tests supply the boolean directly and verify Solace claims and interrupted recovery, not an external writer barrier (`tests/solace_core/test_integration_publish.py:27-37`; `tests/solace_core/test_integration_crashes.py:171-179`). The checked queue stops at `pending_apply`, leaving the target untouched and requiring human approval and pause acknowledgement (`docs/automatic-policy.md:18-31`; `tests/solace_core/test_policy_acceptance.py:53`). The existing integration design excludes uncooperative same-user processes and cannot revoke an external path or open file descriptor (`docs/superpowers/specs/2026-10-16-result-integration-design.md:25,97-103`). A separate cooperative handoff is warranted **if** automatic apply is desired for enrolled writers. It cannot establish global filesystem exclusion.

## Scope, actors and authority

The protected target is the exact registered source root or parent workspace selected by a retained integration plan; there is no caller-supplied destination (`docs/result-integration.md:9`). Its logical project/task owner, real path, and directory identity bind the handoff. Overlapping roots share one exclusion domain, including cross-project overlaps; unrelated projects may continue.

* **Core** owns the durable target gate, epoch, writer roster, grants and publication journal. It serializes handoff with Solace target/task claims and validates plan/check/policy and physical target again before publication.
* **Enrolled writer adapter** wraps an external tool's writes to this target. It registers an identified session and obtains a grant before every writable access, including writes through a previously open descriptor. It acknowledges pause only after stopping new work, draining grants, closing writable descriptors or proving they cannot be used, and persisting its paused state. A tool unable to satisfy this contract is ineligible.
* **Policy worker** may request handoff for a checked candidate only under a future, separately approved automatic-apply policy. Passing checks or queueing an intent gives no publication authority today.
* **Person/operator** retains current manual review, approval, `--writers-paused`, apply and explicit recovery. A CLI actor label records provenance; it is not proof a process stopped. The current socket checks same-user peer credentials (`solace_core/server.py:69-75`) and accepts a printable actor string (`solace_core/protocol.py:94-108`). A private session capability and epoch identify cooperative participation, not defend against a malicious same-user process or direct filesystem access.

The guarantee is conditional: for an explicitly enrolled, compliant set of writers, no acknowledged writer can begin or continue a target write while Core holds that epoch's fence. Arbitrary editors, adapter bypass, background sync, stale writable file descriptors, and unknown writers remain outside it. Zero active grants alone does not prove all possible writers are enrolled. **All target classes remain manual by default.** A dedicated managed parent workspace with a reference adapter is the first possible feasibility candidate, only if probes demonstrate every intended writer path is enrolled and no writable handle survives pause. A cooperative roster alone does not authorize automatic apply to a source root. This boundary is not approval to enable automatic apply anywhere. Never describe the handoff as an OS lock or sandbox.

## Durable protocol

Persist a target gate and monotonically increasing fence epoch in the durable authority that arbitrates Solace target claims. Enrollment binds stable writer identity, fresh session capability, exact target identity and protocol version. Rotate capabilities on reconnect; a display name is insufficient. A grant records session, target, epoch and operation identifier. Reject grants when the gate is not `open`, the epoch is stale, or the target was replaced/relinked. The adapter obtains a grant before each mutation, holds it until that mutation and its writable handle are quiescent, then releases it. Checking the grant and releasing it before a write would leave a race with gate closure; it is not a timeless permission for an open FD.

1. **Open:** Core accepts grants for enrolled sessions. Writers report liveness and release grants after writes are durable enough for integration scanning. An adapter unable to account for in-flight writes is ineligible.
2. **Quiescing:** Core atomically closes the gate to new grants, increments the epoch, and records the target and candidate binding before notifying enrolled sessions. Existing grants must end. A writer replies with `pause_ack(session, target, epoch, last_grant)` only after in-flight writes and writable handles are quiescent. Core requires acknowledgements from every required current session for this exact epoch and zero outstanding grants. Earlier or duplicate acks cannot satisfy the barrier.
3. **Paused:** Core records the roster snapshot, acks and target identity. It rechecks candidate, required check and policy evidence, destination identity/content/head, approval authority and ownership before reserving publication. A changed binding makes the plan stale; no silent reprepare or check rerun. The gate stays closed during checks and writes.
4. **Publishing:** Core holds both writer gate and existing target/journal claims until a terminal receipt or explicit recovery decision. The future automatic path has distinct, auditable policy authorization and handoff evidence; it never fabricates a manual review token or `writers_paused` assertion. Existing validation and crash journal semantics continue (`solace_core/integration_operations.py:104-142,212-253`; `solace_core/integration_publish.py:234-330,376-509`).
5. **Resume:** After a durable terminal receipt, confirmed restoration, or safe no-write abandonment, Core advances the epoch, reopens the gate and issues fresh grants. It notifies adapters after committing the transition. An uncertain journal preserves the fence; elapsed time does not release it. Writers refresh their view and target identity before resuming.

The `pause_ack` is an evidence-bearing barrier, not an assertion by the apply requester. It includes writer/session identity, exact target and epoch, final grant sequence and adapter quiescence statement. Core's own grant ledger is authoritative; a standalone acknowledgement is insufficient. Retain barrier evidence with the receipt or interrupted operation for audit and replay.

## Liveness, expiry, crash and storage

Heartbeats detect missing writers; they do not prove quiescence. Missed heartbeat, disconnect, process crash, grant timeout, malformed ack or unknown outstanding grant makes handoff **uncertain** and blocks automatic publication. Lease expiry cannot reclaim a write possible through an open FD. The adapter must prove cessation, or a person handles the target after inspection. A restarted writer re-enrolls with a new capability and current epoch; old acks are never reused.

After Core restarts, it reconstructs durable gate, epochs, roster, grants and publication journal before accepting grants. `quiescing`, `paused` and `publishing` remain closed and uncertain until exact sessions and target are reconciled. Process absence does not imply pause. Core does not auto resume/rollback interrupted publication (`docs/result-integration.md:70-90`). Missing, replaced, moved or relinked targets preserve claims and require existing explicit location/recovery proof. Handoff identity follows verified logical relocation, never path-string substitution. Policy disablement stops new handoffs but cannot clear an in-progress fence or journal.

Guard the exact parent workspace for child apply and the registered source for root apply. A writer active in multiple independent domains needs a separate grant/ack in each. Realpath/identity overlaps cannot have independent exclusive gates; share a gate or refuse automatic apply. Retained claims and unavailable project stores continue to block ambiguous ownership. If complete overlap detection is unavailable, fail closed for that target class. Durable-store/schema changes need separate migration review and preview; none are specified by this design.

## Compatibility and limits of the claim

Manual apply remains valid: a person reviews the exact plan, supplies its approval token, pauses external writers by their own procedure, and asserts `--writers-paused`. Recovery stays explicit. A future machine handoff is a separate apply mode with separate authorization and receipt provenance; it cannot be inferred from the manual boolean. Checked queue continues to mean ready for human decision until that mode is designed, approved and implemented. Manual apply itself is not machine-verified exclusion.

This contract could substantiate cooperative quiescence for enrolled adapters at the exact target/epoch. It cannot substantiate that every process is paused, that a direct editor cannot write, that the filesystem revoked an FD, or that policy checks equal human review. Automatic apply is inappropriate where write paths cannot be enumerated and enrolled. Whether cooperative-only coverage is acceptable for any source or parent workspace is a product/operator decision before implementation; safe default is manual.

## Acceptance probes

Use a disposable project and a real external writer through a reference adapter. Observe actual file writes and grant records; an in-memory fake alone cannot validate this contract.

1. **Positive control:** Writer A obtains a grant and edits the target. Core closes the gate, waits for A to finish and acknowledge the current epoch, then applies an exact checked/authorized candidate. A grant requested while paused is refused. Receipt records barrier; a new-epoch grant succeeds only after durable completion and refresh.
2. **Negative controls:** Keep A's grant active or withhold its current-epoch ack while plan/check evidence is valid. Automatic apply remains pending with unchanged target and no application receipt. Separately, after the gate closes, make A attempt a real write through the reference adapter and verify that no target mutation occurs and the attempt is refused or held. A stale-epoch or wrong-session ack cannot unblock either case. These are the principal falsifying probes for the proposed barrier.
3. **Uncooperative edit:** An unenrolled editor or open writable FD mutates after ack. The probe demonstrates the protocol cannot prevent it; Solace detects a target change where existing checks can, fails closed, and makes no broader exclusion claim. If direct writing races publication, report the limitation rather than call it a safety pass.
4. **Crash matrix:** Kill writer before/after ack, kill Core before/after gate commit and during publication, disconnect/reconnect, expire heartbeat with outstanding grant. Restart retains fence and uncertain journal until explicit recovery; timeout/reconnect never auto resume.
5. **Bindings and isolation:** Change target bytes/identity, policy/check binding or enrolled roster between handoff and publication; invalidate the attempt. Exercise root source, child parent workspace, overlapping paths across projects and unrelated projects. Overlap shares gate or refuses; unrelated work proceeds.
6. **Compatibility:** Current manual apply/recovery still accept explicit boolean and retain receipts. New automatic provenance is distinct and reconstructable. Replayed request IDs return original outcome without a second publication.

## Implementation phases and gates

1. Keep all targets manual while deciding which tools can wrap **all** writes. Use a dedicated managed parent workspace and reference adapter as the first feasibility candidate; prove all intended write paths enroll and no writable handle survives pause. Source-root automatic apply needs a separate, stronger coverage decision and is not justified by a cooperative roster alone. If no target qualifies, keep checked queue manual.
2. Specify and review versioned adapter protocol, target identity, durable roster/grant ledger, epochs and crash invariant. Prove a reference adapter cannot mutate under a revoked grant, including open-FD behavior. This is the feasibility gate.
3. Implement Core gate and adapter in an isolated change with positive, negative, crash and overlap probes. Keep automatic publication disabled until the probes pass on a real Unix socket and filesystem.
4. Design separate policy authorization and receipt provenance for automatic apply; integrate barrier with exact plan/check/policy revalidation and existing publication/recovery. Review schema migration, installer preview and disposable installed acceptance independently before a real-project upgrade.
5. Consider enabling only explicitly managed parent workspaces after separate operator review and approval of the implementation and coverage evidence. This design itself authorizes no automatic apply. Expose failed/uncertain handoffs and manual recovery. Installation or store upgrade remains a separate authorized gate.
